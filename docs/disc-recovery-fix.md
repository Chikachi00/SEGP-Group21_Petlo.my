# 飞盘背景漏检修复

更新日期：2026-10-12。修复采用独立入口，原检测、狗追踪、飞盘第一版、URS 和原视频均保留。当前结果在 `outputs/disc-tracking-v2/`；本轮中间实验另存于 `disc-tracking-v2-initial/`、`disc-tracking-v2-motion-initial/`，不作为交付版本。

## 修复的问题

正面第二次飞行约 11.25–11.97 秒期间，部分原画面仍可见蓝盘，但保存的模型检测主要只剩手持盘。第一版在长缺失后结束原 ID，恢复时建立新 ID，导致同一次飞行分成两段。局部放大重新调用同一模型也未稳定找回中间帧，因此增加受限的局部外观跟踪。

`cv/disc_recovery.py` 为已确认且近期正在移动的飞盘建立颜色参考。没有相容的原检测时，围绕运动预测位置检查当帧原图中的颜色连通区域，核对颜色、与周围背景的对比、面积、形状、运动门限和唯一性；符合条件时作为局部外观观测。无法可靠恢复时，最多每个目标 0.15 秒尝试一次局部 YOLO 重检，每帧最多两次。没有证据时仍保留预测或丢失。

颜色参考来自模型观测；局部外观跟踪最多持续到最后模型锚点后的 0.8 秒。纯位置预测仍只显示 0.12 秒，ID 的无观测保留时间仍为 0.35 秒。局部画面观测可以刷新位置时间，纯预测不会刷新。候选同时符合另一条轨迹的运动门限时，拒绝将它作为局部恢复证据。

长缺失后的一次重新匹配可能造成跨间隔位移推算出的速度异常增大。只有在缺失超过预测时限、速度相对之前超过两倍且超过画面对角线每秒一半时，才暂时保留缺失前的速度，等待新的相邻观测更新。这个保护不适用于普通速度变化，也不构成真实物理速度测量。

## 输出如何解读

蓝色实框及轨迹线为画面观测，包括模型检测和局部外观跟踪；局部外观观测在视频上额外标为 `VISUAL`。黄色虚框是纯位置预测；灰色框是待确认候选。缺失间隔不被插值成实测线。

`states.jsonl` 的 `measurement_source` 区分：

| 来源 | 含义 | confidence |
|---|---|---|
| `saved_detector` | 原始检测文件中的模型框 | 原模型值 |
| `local_yolo` | 对当帧局部图像重新调用本地模型的框 | 重检模型值 |
| `local_visual` | 当帧有证据的颜色区域跟踪 | 空值，不冒充模型置信度 |
| 空值 | 没有当前画面观测，例如预测或丢失 | 空值 |

`trajectory.csv` 也增加了来源列；实测中心与预测中心分列。局部框描述可见颜色区域，可能只覆盖飞盘的一部分，中心不能视为精确真值。`tracks.jsonl` 继续兼容原复查接口：画面观测使用 `detected`，纯预测/缺失的框和置信度为空。后续事件算法应结合状态文件的来源，而不能把所有 `detected` 都当作 YOLO 检测。

```powershell
# Run these commands from the repository root
Start-Process 'outputs\disc-tracking-v2\index.html'

.\.venv\Scripts\python.exe cv\track_disc_recovered_video.py `
  --detections outputs\front_disc_enhanced.jsonl `
  --output-dir outputs\disc-tracking-v2\front-v1

# 侧面
.\.venv\Scripts\python.exe cv\track_disc_recovered_video.py `
  --detections outputs\multi-angle-check\side_disc_enhanced.jsonl `
  --output-dir outputs\disc-tracking-v2\side-v1

# 手持
.\.venv\Scripts\python.exe cv\track_disc_recovered_video.py `
  --detections outputs\multi-angle-check\handheld_disc_enhanced.jsonl `
  --output-dir outputs\disc-tracking-v2\handheld-v1

# 三段完整结果已生成后建立新版回看页
.\.venv\Scripts\python.exe cv\build_disc_recovery_review.py

# 自动测试
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

只加载已有本地模型，不联网下载。相同来源、代码、设置和工具版本会校验缓存；更改参数时使用新输出目录。`--no-roi-model` 可关闭局部 YOLO 重检，保留局部外观跟踪；`--max-visual-seconds` 设置参考有效时限，上限为 1 秒。窗口实验建议从漏检前开始，例如 `--start 10.5 --end 12.8`，并使用新目录，让轨迹先建立可靠参考。窗口 ID 与全片 ID 不直接对应。

## 验证与前后比较

原有 59 项测试与新增 12 项测试，共 71 项通过。新增覆盖局部颜色观测、置信度分离、参考到期、真正消失、候选歧义、错误颜色、静止背景、跨轨迹竞争、局部模型坐标映射、速度异常保护、真实变帧率回放及缓存。三个动作视频完整处理 4542 帧，验证输出帧数、尺寸、真实时间、结果格式与原文件内容哈希。

针对报告的问题，核对源帧 675–739（11.25–12.317 秒）：第一版空中目标的接受观测为 17 帧，分成两个 ID；修复版为 63 帧，保持一个 ID。在原来长缺失覆盖的帧 676–718 中，补充了 41 帧局部外观观测，其余两帧使用原模型观测。源帧 730–731 仍是短缺失，保留预测而不编造实测。

少量全景、原尺寸裁剪、放大浏览图与坐标映射在 `outputs/disc-tracking-v2/audit/`。每角度默认检查一个窗口；每批最多 8 张独立图像。新回看页也能选择一个 ID、开关预测点，并显示当帧外观观测个数。

`outputs/disc-tracking-v2/comparison.json` 核对相同视频内容、完整源帧和时间范围，记录各来源的观测、轨迹数量、运行时间、原来接受但新版未接受的模型框，以及新增接受的原模型框。这些差异需要人工核查，不能直接视为改善或错误。不同版本 ID 编号可能变化；ID 数量不是投掷次数。

|---|---:|---:|---:|---:|
| 正面 | 2169 | 3 | 62 | 0 |
| 侧面 | 6333 | 22 | 64 | 3 |

侧面源帧 1235–1237（约 20.604–20.637 秒）有三条原版接受的模型框未被新版接受，保留在比较记录和 `audit/side-regression/` 中，作为回归候选，不能宣称所有片段都有改善。手持 4.004 秒的一次嘴边蓝盘局部外观观测可见，但之后仍会超过参考时限并丢失。

原 `review-results` 能检查新版轨迹并生成诊断窗口，但其自动前后比较会在同帧轨迹记录量改变时拒绝比较。不要为了通过比较而删除轨迹记录；本次使用上述同源帧比较记录。仍没有人工标签，无法报告精确率或召回率。

## 仍有的限制

这次修复解决了所报告的蓝盘长断轨案例，不保证所有背景下连续追踪。相似颜色干扰、严重模糊、局部遮挡、相机运动及颜色参考变化都可能导致拒绝恢复或误匹配。浅色、低饱和度目标可能没有可靠颜色参考；手持视频后段仍可能丢失。四段样本只能支持原型验证，投掷、接盘、失误和评分尚未实现。
