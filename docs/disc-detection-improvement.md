# 飞盘检测增强与对照记录

初版 YOLO 在正面视频中只在少量帧检测到飞盘。12 秒附近可以看到空中飞盘和人手里的另一只飞盘，原版都可能漏掉。18 秒附近还存在遮挡、手持飞盘与背景重叠的问题。

## 本次改动

新增 `cv/detect_disc_video.py`：

- 全景输入由默认 640 提高至 1280，保留更多小目标像素。
- 额外按 2×2、20% 重叠网格提取原分辨率区域，以 960 输入单独检测飞盘。
- 把局部框映射回原尺寸显示画面，再合并重叠重复框；保留空中与手持的多个独立飞盘。
- 狗、人用全景检测；飞盘阈值可单独调整。默认仍用 0.25，避免把明显的低分背景候选全部纳入。
- 使用同一份真实源帧时间索引，通过 FFmpeg 顺序提供原尺寸画面，并验证 PTS 与方向。没有插帧或用假框填补漏检。
- 输出带框 MP4、逐帧检测 JSONL、配置与耗时摘要，方便复现同一试验。

这次不需要新模型或新依赖，也不自动下载权重。输入与局部检测的依据见 [Ultralytics 预测参数](https://docs.ultralytics.com/modes/predict/) 和 [小目标分块检测说明](https://docs.ultralytics.com/guides/sahi-tiled-inference/)；这里用现有库实现重叠局部推理，未新增 SAHI 依赖。

## 初步对照

在同一个模型、同一组 40 个原视频帧（11.5–13.5 秒和 17.5–19.5 秒，各约 10 fps）上进行初筛：

| 设置 | 全景输入 | 飞盘阈值 | 局部检测 | 有飞盘候选的帧 |
|---|---:|---:|---|---:|
| 原版 | 640 | 0.25 | 无 | 2/40 |
| 只降低阈值 | 640 | 0.10 | 无 | 3/40 |
| 提高全景分辨率 | 1280 | 0.10 | 无 | 11/40 |
| 加入局部检测 | 640 | 0.10 | 2×2，960 | 22/40 |
| 局部候选过滤低分框 | 640 | 0.25 | 同上 | 19/40 |

画面复核：源帧 720（12.000 秒）中的空中飞盘从原版未检测，到高分辨率约 0.40，再到局部检测约 0.69；人手里的粉色飞盘在局部检测中约 0.71。局部检测同时把树枝认成约 0.15 的飞盘，因此采用 0.25 默认阈值。源帧 1080（18.000 秒）的手持飞盘仍未恢复，不能认为问题已解决。

再对 **11.5–13.5 秒全部连续 120 个源帧** 跑新入口，保持 0.25 阈值：

| 设置 | 完整处理帧 | 有狗检测的帧 | 有飞盘检测的帧 | 有人检测的帧 |
|---|---:|---:|---:|---:|
| baseline，640 全景 | 120 | 101 | 11 | 120 |
| enhanced，1280 全景 + 2×2 局部 | 120 | 116 | 103 | 120 |

两版输入、源文件内容及帧编号相同。带框片段、逐帧记录和配置摘要位于本地 `outputs/disc-improvement/`。这些是检测存在计数，不能解释为准确率或空中飞盘召回率；手持飞盘也会计入，需要逐目标核查。

## 运行

在仓库根目录：

```powershell
.\.venv\Scripts\python.exe cv\detect_disc_video.py '<sample-video-directory>\Landscape_Tripod_FrontView.mp4' --output outputs\front_disc_enhanced.mp4
```

默认完整处理原视频。短片段实验可加 `--start 11.5 --end 13.5`，起点含、终点不含，均使用真实时间索引。需要更快时加 `--disc-grid 0`，只做 1280 全景检测。对照模式用 `--mode baseline`，并保存到另一个输出名。

降低飞盘阈值可用 `--disc-confidence 0.15`，不会同时降低狗、人阈值，但要复核新增误检。`--imgsz`、`--tile-imgsz`、`--overlap` 可改变输入与网格参数；`--device` 默认 CPU，`--cpu-threads` 默认 4。输入源必须在已完成的资料包中，模型文件必须已在本地。

## 输出与下一轮

- MP4 是人工浏览回放，按名义帧率播放；JSONL 保存实际源帧编号、PTS 和相对时间。
- 每行 JSONL 是一个帧，`detections` 数组包含类别、原尺寸边界框、置信度和 full/tile 来源；空数组只说明这帧没有检测结果。
- 当前没有跨帧轨迹身份，检测 JSONL 不能直接交给轨迹接口 `review-results`。需要后续正式追踪接入，不能编造稳定 ID 或把无检测当作已证实目标缺失。
- 局部检测更慢，背景误检仍可能出现；这里只对正面视频选定片段做过比较，侧面、手持仍需后续验证。
- 本轮未训练模型，也没有人工真值指标。下一轮先核查空中飞盘、手持飞盘、地面飞盘及背景误检，再建立小规模人工标签集和正式轨迹关联。
